KKS Code Reference — Supercritical Thermal Plant

Kraftwerk-Kennzeichensystem (Power Plant Identification System) codes for a coal-fired supercritical unit, with a full tag-building methodology and a click-down Area → System → Subsystem explorer — boiler, turbine-generator, coal handling, cooling water, water treatment, electrical, and I&C — plus the finer signal suffix codes (XB, XG, XH, XQ...) appended after an equipment tag to identify an individual command or feedback signal. Searchable by code or by what a system actually does.

KKS Tag Methodology

A complete KKS tag is built from four breakdown levels, read left to right, each narrowing the identification further. Worked example — a specific pump on the economizer system of Unit 1:

10 HAC 01 AP 001

Level 0 — Total Plant Key: 10

Identifies the unit itself (e.g. Unit 1 of a multi-unit station). Plant-and-project-specific, agreed once at project start.

Level 1 — Function Key (Process Code): HAC

The area/system/subsystem code covered by the explorer below: F1 (H, the main group — boiler), F2 (A, narrows to the pressure system), F3 (C, narrows to the economizer specifically). This is the part that says WHAT the equipment does, independent of how many identical ones exist.

Level 2 — Equipment Unit Key: 01 + AP

A sequence number (01 = the first economizer on this system, distinguishing it from a second if one exists) followed by an equipment-unit letter code from a separate table (AP = pump, AA = valve, AC = heat exchanger, and so on) identifying WHAT KIND of physical device this specific item is.

Level 3 — Component Key: 001

Numbers one individual component belonging to that equipment unit, e.g. a specific motor, sensor, or terminal box mounted on the pump itself. Not every tag needs this level — it’s only added when identifying a part OF the equipment unit, not the unit as a whole.

Put together: 10HAC01AP001 reads as "Unit 1, economizer system, first instance, a pump, component 001 of it" — unique, and readable without a lookup table once you know the four levels. The area/system/subsystem explorer below builds exactly the Level 1 portion of this — pick an area, then a system, then a subsystem, to land on its F1F2F3 code.

Signal Suffix Codes

A KKS equipment tag identifies a device (a drive, a valve). A signal suffix appended after it identifies one individual command or feedback bit on that device: MAB10AA001 might be a specific pump, and MAB10AA001XB01 its "on" feedback — XB is the signal category letter, 01 is the specific function within it. This is the layer that actually answers "which signal is the ON feedback": an X-prefix code specifically marks a signal coming back FROM the field (a status/confirmation), as distinct from a command going TO it, which instead uses the separate Application Code scheme (Y-prefix, e.g. MAB10AA001YB01) covered further down — real projects commonly also wire the complementary "confirmed OFF" feedback 50 numbers later (XB51) alongside XB01, so a genuine OFF state can be told apart from a stuck or failed-to-report contact.

About This Calculation

KKS (Kraftwerk-Kennzeichensystem, the Power Plant Identification System) is the standard used across most large coal and gas thermal plants worldwide — including the great majority of Indian supercritical units — to give every system, piece of equipment, and signal a unique, unambiguous tag, independent of language or drawing. A code like HAC10 or LBA20 isn’t arbitrary: reading left to right, the letters narrow down from plant area to specific system, and the trailing digits number the individual instance. This reference organizes the codes actually used on a supercritical coal-fired unit by the plant area an engineer would actually search by — boiler pressure parts, steam-water cycle, turbine-generator, coal handling, cooling water, and the rest — rather than requiring you to already know which of the roughly two dozen KKS main-group letters a system falls under. It draws on the VGB KKS guidelines and real project-issued KKS lists (including supercritical unit documentation), not a single vendor’s abbreviated cheat sheet.

Frequently Asked Questions

What do the letters in a KKS code actually mean?

Reading left to right, each letter narrows the identification further: the first letter is the main plant area (H for the boiler, L for the steam-water cycle, M for the turbine-generator, and so on), the second letter narrows that to a system within the area, and a third letter (where used) narrows it to a specific sub-system. The digits that follow number the individual instance — e.g. which of several identical pumps.

Why does this reference call out HAG specifically as "not used in a natural-circulation boiler"?

It’s one of the few places the KKS code itself tells you something about the unit’s design: HAG is the boiler’s circulation system. A drum-type (natural or forced circulation) boiler has one; a once-through supercritical boiler, which has no steam drum at all, does not — so whether a real KKS list for a given unit includes an HAG tag is itself a quick, genuine tell for which boiler type you’re looking at.

Why does the steam-water cycle (L) have its own water treatment codes (LD) separate from the plant’s general water treatment (G)?

They serve genuinely different water qualities and purposes. G covers raw, service, and drinking water treatment for the plant as a whole. L’s own LD codes cover condensate polishing and deaeration — treatment of the actual high-purity boiler feedwater circulating inside the steam-water cycle itself, which has far stricter chemistry requirements than general plant water.

Is KKS still the current standard, or has it been replaced?

KKS remains very widely used, especially on existing plants and across India, China, and the Middle East, but it is gradually being superseded on new projects by RDS-PP (Reference Designation System for Power Plants), an IEC-aligned successor with a broadly similar area-first structure. Most engineers working on brownfield or existing supercritical units will still encounter KKS directly.

Does every plant use exactly these codes?

The main-group letters and the most common subgroups (economizer, superheater, feedwater pump, and so on) are standardized and consistent project to project, which is the whole point of KKS. Lower-level details — exact numbering, some project-specific subgroup assignments — are agreed per project, so always confirm against your own plant’s actual KKS list for anything safety- or maintenance-critical; treat this as a reference for understanding the system, not a substitute for your plant’s documentation.

What do the numbers after the letters mean in a full tag like 10HAC01AP001?

They come from two entirely different, separately-agreed number tables, which is easy to miss. 01 (right after HAC) numbers WHICH instance of the economizer system this is — relevant if the unit has more than one. 001 (at the very end) numbers a specific component belonging to the equipment unit AP identifies — e.g. one particular sensor or terminal box on that pump. Neither number is arbitrary, but they answer different questions: "which system instance" versus "which part of this specific device".

The explorer shows some systems with no subsystems listed below them — is that a gap in this reference?

No — for a system like CW (control rooms), the two-letter system code is itself the most specific standardized KKS tag; there’s no further F3 breakdown to show because the real system doesn’t have project-agnostic subsystem codes at that level. The explorer says so directly rather than just showing an empty, unexplained space.

How is a specific feedback or command signal actually named — e.g. the "on" feedback for a pump?

That’s what the signal suffix codes (further down this page) are for, a finer layer within the same KKS system: appended directly after a device’s own equipment tag, a code like XB01 identifies one individual feedback bit read back from it. XB01 specifically covers "on/open" feedback — confirmation from the drive that it is actually on, not the command that told it to turn on — and many projects also wire the complementary "confirmed off" feedback 50 numbers later (XB51) alongside it, so a genuine OFF state can be told apart from a stuck contact.

What code is used for a command signal, and how do DI, DO, AI, and AO map to KKS?

Commands use a separate KKS suffix scheme from the X-prefix Signal Code covered above — the Application Code, prefixed Y instead of X, officially listed in the McGraw-Hill KKS appendix alongside its Signal Code counterpart. Mapped to the usual PLC/DCS signal classes: DI is XG (a binary signal wired straight from a field switch); AI is XQ (a continuous incoming analog reading); DO is YB (a binary/discrete command — on/off, open/close — sent out to a drive); AO is YQ (a continuous outgoing analog value, e.g. a 4-20mA setpoint to a valve positioner). All four are covered in the Signal Suffix Codes section below, alongside the confirmed XB01/YB01 command-versus-feedback pair.
